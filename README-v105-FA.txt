پچ v105 — تطبیق مقدارهای PDF با BOQ و نگهداری عملیات بدون نرخ

نصب روی v104: ZIP را در ریشه پروژه ventra استخراج و فایل‌های هم‌نام را جایگزین کنید؛ src را داخل src قرار ندهید.
این پچ نیاز به SQL، متغیر محیطی جدید یا نصب وابستگی جدید ندارد.

اصلاحات بر اساس خروجی sami-boq (7).xls:
۱. مقدار خاک‌برداری دیگر برای حمل خاک، تخلیه خاک یا خاک‌ریزی استفاده نمی‌شود.
۲. تعداد نقاط روشنایی دیگر به تعداد چراغ LED یا downlight نسبت داده نمی‌شود. تطبیق با ردیف نقاط روشنایی عمومی مجاز است.
۳. یک مقدار مستند بین چند گزینه کاتالوگ تکرار نمی‌شود. اگر چند گزینه تطبیق داشته باشند، انتخاب مشخصات و نرخ نیازمند بررسی است.
۴. مقدار مستند بدون تطبیق کاتالوگ، با یک ردیف PDF مستقل و نرخ صفر حفظ می‌شود؛ صفر بودن نرخ به معنی رایگان بودن عملیات نیست. این ردیف تا تعیین مشخصات و نرخ در بودجه قیمت‌گذاری‌شده و مبلغ قرارداد وارد نمی‌شود.
۵. ردیف فاقد مقدار دیگر برچسب measured_takeoff نمی‌گیرد؛ مبنای مقدار آن unavailable است.
۶. بررسی پوشش عملیات در دستور تحلیل PDF گسترش یافته است: بتن هر جزء، قالب‌بندی، کف‌پوش‌ها، دیوارچینی، رنگ، عایق‌کاری، تأسیسات و محوطه. عایق‌کاری از مساحت کف یا کاشی حدس زده نمی‌شود. قطر لوله، ظرفیت کولر یا رده بتن از قیمت کاتالوگ انتخاب نمی‌شود.
۷. عنوان ردیف‌های جدید و وضعیت «مقدار ثبت شده / نرخ و مشخصات نیازمند تعیین» برای فارسی و عربی ترجمه شده است.
۸. اگر پایگاه قواعد/قیمت خالی باشد، مسیر PDF به قیمت‌های حدسی بازنمی‌گردد؛ مقدارهای مستند با نرخ نامشخص حفظ می‌شوند.

پس از نصب:
۱. npm run build را اجرا کنید.
۲. تغییرات را در GitHub commit و push کنید و منتظر Published شدن آخرین commit در Netlify بمانید.
۳. همان PDF اصلی را دوباره Analyze کنید تا دستور تحلیل جدید اجرا شود؛ سپس Generate BOQ را بزنید.
۴. از Drawings بخش PDF page analysis report، فایل ventra-pdf-analysis-report.json را دانلود کنید و همراه خروجی جدید BOQ ارسال کنید.

مرز اعتبار:
این اصلاحات خطاهای قطعی تطبیق و گم‌شدن مقدارهای موجود را پوشش می‌دهند؛ تضمین استخراج کامل از هر PDF نیستند. مقدارهایی که AI استخراج نکرده یا شواهدشان متعارض/ناقص است، با این پچ ساخته نمی‌شوند. بدون گزارش JSON جدید، علت همه ردیف‌های خالی قابل تعیین نیست.
مقدارهای دارای سند PDF همچنان استخراج AI و نیازمند کنترل مهندس هستند. نرخ و مشخصات باید برای همان پروژه تأیید شوند؛ جمع پایین‌تر نشانه دقت بیشتر نیست. مبلغ قرارداد تا تأیید ردیف‌ها می‌تواند صفر بماند.
تست‌های این پچ روی داده‌های کنترل‌شده و مسیر تبدیل شواهد به ردیف و خروجی انجام می‌شود؛ تحلیل زنده OpenAI و دیتابیس کاربر در این محیط اجرا نشده است.

اعتبارسنجی این نسخه: ۵۱۴ تست موفق، ۲۹ تست مرتبط موفق روی کد نهایی، بیلد production Next.js موفق، بیلد تابع پس‌زمینه Netlify موفق، و کنترل ساختار strict JSON schema موفق.
