# Ventra v47 — کنترل تطابق رندر با پلان

این نسخه کامل پروژه است. فایل‌های نسخه را در پوشه جدا استخراج کنید، فایل خصوصی `.env.local` خودتان را نگه دارید، سپس `npm ci` و `npm run dev` را اجرا کنید. برای این تغییر هیچ SQL جدیدی لازم نیست.

در بخش رندر واقعی طراحی، تصویر اصلی پلان را انتخاب و تولید را اجرا کنید. اکنون مسیر شامل سه مرحله است: تحلیل فضاها و روابط پلان، تولید تصویر با همان فهرست، و مقایسه تصویری خروجی با پلان اصلی. اگر تحلیل مبهم باشد یا بررسی اختلاف/ابهام تشخیص دهد، تصویر به عنوان موفق برگردانده و ذخیره نمی‌شود. بررسی باید تمام شناسه‌های فضا را پوشش دهد؛ اتاق حذف‌شده، بالکن جابه‌جا و فضای اضافه سبب رد می‌شوند. تصویر قدیمی فاقد بررسی به صورت خودکار نمایش داده نمی‌شود و باید دوباره تولید شود.

مهلت کل پردازش سرور ۲۷۰ ثانیه و انتظار درخواست در مرورگر ۳۰۰ ثانیه است. پیام رد تطابق، ابهام پلان و پایان انتظار به سه زبان اضافه شده است. تلاش مجدد خودکار وجود ندارد.

این مسیر سه درخواست API دارد: دو تحلیل تصویری و یک تولید تصویر. هزینه API نسبت به نسخه قبل بیشتر می‌شود؛ حتی خروجی ردشده ممکن است هزینه داشته باشد. سهمیه فعلی برنامه همچنان یک عملیات طراحی حساب می‌کند. بعد از پایان مهلت، قبل از تکرار مصرف را بررسی کنید. مدل بررسی اختیاری `OPENAI_PLAN_REVIEW_MODEL` است؛ در نبود آن مدل `OPENAI_3D_PREVIEW_MODEL` و سپس `gpt-5.6-sol` استفاده می‌شود. دسترسی API به مدل‌ها لازم است.

محدودیت مهم: این یک کنترل تصویری مبتنی بر AI است، نه قفل هندسی یا تایید مهندسی. تحلیل اولیه یا بررسی نهایی ممکن است اشتباه کند. این نسخه تضمین تطابق کامل نمی‌دهد و مشکل کیفیت مدل تعاملی قابل‌چرخش را حل نمی‌کند. رندر تصویر طراحی پیشنهادی است و BOQ را تغییر نمی‌دهد. مسیر DWG/APS در این تغییر ویرایش نشده است. هیچ تعداد اتاق یا چیدمان مختص این نمونه در کد ثابت نشده است.

آزمایش‌ها با پاسخ‌های شبیه‌سازی‌شده، حذف اتاق، انتقال بالکن، فضای اضافه، پاسخ ناقص و خرابی بررسی را پوشش می‌دهند. تولید واقعی با API و پلان کاربر در این محیط آزمایش نشده؛ نتیجه زنده هنوز نیاز به ارزیابی دارد.
