# ونترا — زیرساخت تجاری، ۷ اکتبر ۲۰۲۶

این بسته سورس کامل نسخه موجود به همراه اصلاحات تجاری است. آماده‌بودن سورس به معنی تأیید انتشار عمومی، دقت همه نقشه‌ها یا تضمین درآمد نیست.

## ترتیب نصب

۱. فعلاً روی نسخه فعال مشتری‌ها جایگزین نکن. یک کپی جدا از پوشه ventra بساز و .env.local خودت را فقط محلی نگه دار.
۲. ابتدا scripts/Ventra-Database-Check.sql را در SQL Editor پروژه Supabase اجرا کن. این فایل فقط ساختار را می‌خواند، تغییری نمی‌دهد و داده مشتری برنمی‌گرداند. نتیجه را برای بررسی بفرست.
۳. migration جدید به جدول projects با id و user_id از نوع uuid و زیرساخت Team & Contract وابسته است. اگر migration قبلی 20261006_project_control.sql روی پروژه اجرا نشده، پیش‌نیاز باید پس از بررسی ساختار اعمال شود. فایل جدید supabase/migrations/20261007_commercial_foundation.sql است. اجرای آن روی دیتابیس آنلاین در این محیط انجام یا تأیید نشده است.
۴. در .env.local محلی، SUPABASE_SERVICE_ROLE_KEY را تنظیم کن. این کلید فقط سمت سرور است: NEXT_PUBLIC نداشته باشد و در چت، Git یا فایل ارسالی قرار نگیرد. از تنظیمات API پروژه Supabase کلید server-side را بردار. تنظیمات موجود Supabase/OpenAI/Stripe را حفظ کن.
۵. از ریشه پروژه node scripts/commercial-preflight.mjs را اجرا کن. این فقط وجود نام تنظیمات را بررسی می‌کند؛ هیچ کلیدی چاپ و درخواست پولی ارسال نمی‌کند.
۶. npm install و npm run build را در همین پوشه اجرا کن. ابتدا در محیط آزمایشی Stripe/Supabase، با حساب تست مراحل زیر را بررسی کن؛ سپس راه‌اندازی عمومی انجام شود.

## تغییرات واقعی

- مسیرهای تحلیل نقشه، طراحی و پیش‌نمایش 3D و تولید BOQ ورود و دسترسی پروژه را بررسی می‌کنند. فقط مالک و مدیر/سرپرست عضو می‌توانند تحلیل اجرا کنند.
- اشتراک active یا trialing با Price ID تنظیم‌شده لازم است. past_due، unpaid، canceled و قیمت اشتراک نامرتبط مجوز تحلیل نمی‌دهند. اشتراک مالک پروژه ملاک اعضای مجاز است.
- سهمیه پیش‌فرض: ۳۰ درخواست تحلیل در ماه تقویمی UTC برای اشتراک فعال، ۵ درخواست هنگام trial. نقشه/طراحی/پیش‌نمایش از یک سهمیه مشترک استفاده می‌کنند. درخواست ناموفق پس از پذیرش هم یک سهمیه مصرف می‌کند. BOQ سهمیه تحلیل مصرف نمی‌کند، ولی دسترسی اشتراک لازم دارد.
- شمارنده در دیتابیس با قفل تراکنش ثبت می‌شود؛ با restart سرور پاک نمی‌شود. درخواست تکراری موفق در همان فرآیند، تا پنج دقیقه پاسخ کش‌شده می‌گیرد. درخواست تکراری ثبت‌شده پس از restart دوباره AI را اجرا نمی‌کند؛ خطای مشخص می‌دهد تا نتیجه بررسی شود.
- کش پیش‌نمایش به شناسه کاربر و درخواست محدود شده است. الگوریتم هندسه، دیوارها، بازشوها، متریال و جایگذاری مبلمان در این مرحله تغییر نکرده‌اند. فقط اتصال شبکه تحلیل در Viewer تغییر کرده است.
- Billing مصرف و زمان reset سهمیه را نشان می‌دهد. Pricing مبلغ و دوره واقعی Price تنظیم‌شده در Stripe را می‌خواند؛ عدد ثابت ۱۰۰۰ درهم حذف شده است. قیمت واقعی Stripe تغییر نکرده و تخفیف یا پلن جدید ساخته نشده است.
- در BOQ، Estimate و Quotation دکمه‌های Save shared version و Load shared version وجود دارند. این ذخیره صریح است، نه autosave ابری. قبل از آن کوتیشن را با Save Draft ذخیره کن. BOQ/برآورد/کوتیشن/لوگو و سربرگ یک snapshot مشترک می‌سازند.
- نسخه ابری دارای revision است. اگر نفر دیگری ذخیره کند، تغییر تو روی نسخه جدید بدون بارگذاری و بررسی جایگزین نمی‌شود. Load shared version با تأیید کاربر، پیش‌نویس مرورگر را جایگزین و نسخه قبلی را محلی پشتیبان‌گیری می‌کند. این جایگزین بکاپ خارج از مرورگر نیست.
- تنظیمات ذخیره‌شده Estimate هنگام بازگشت بازیابی می‌شوند؛ نرخ سفارشی با preset پیش‌فرض بی‌خبر عوض نمی‌شود.
- چت راهنما در بسته موجود است؛ AI پشتیبانی نیازمند ورود و تنظیمات سرور است. سقف مشترک دیتابیس ۱۰ درخواست در روز UTC دارد. راهنمای آماده بدون مصرف AI کار می‌کند.
- صفحه اصلی روی مسیر نقشه، BOQ، برآورد قابل بازبینی و کوتیشن تمرکز می‌کند؛ ادعای دیتابیس قیمت زنده حذف شده است.

## کنترل انجام‌شده و محدودیت‌ها

۶۴ آزمون مرتبط تجاری/زمان‌بندی/بخش‌های نمایش 3D موفق شدند. ساخت محلی با Next.js نصب‌شده 16.2.10 و webpack گذشت؛ package.json نسخه 16.3.8 را دارد و تست واقعی آن نسخه روی سیستم شما باقی است. درخواست HTTP بدون ورود برای پنج مسیر AI، چت و مصرف Billing پاسخ 401 گرفت؛ هیچ API پولی آزمایشی فراخوانی نشد.

کل مجموعه آزمون‌های تاریخی سبز نیست: چند تست قدیمی raster با قرارداد خروجی فعلی سازگار نیستند، دو تست متریال به نسخه بسیار قدیمی TV و DWG reset ارجاع می‌دهند، و وابستگی PGlite برای تست SQL حاضر نبود. برای سبزکردن ظاهری آزمون‌ها، هندسه یا assertions قدیمی تغییر داده نشدند. اجرای واقعی migration، قوانین دسترسی و تعارض هم‌زمان در PostgreSQL هنوز باید انجام شود.

تست مرورگر قبلاً مجوز نگرفت؛ در این مرحله آزمون کلیک یا مرورگر با ابزار جایگزین انجام نشد. اتصال زنده Stripe، Supabase، OpenAI و APS، خطای پرداخت، تمدید، لغو، بازیابی روی دستگاه دوم و صحت فایل‌های واقعی مشتری هنوز تأیید نشده‌اند. این بسته نباید به عنوان انتشار عمومیِ تأییدشده تلقی شود.

## مسیر اولین فروش

اولین عرضه را محدود به پروژه کوچک بازسازی/فیت‌اوت و خروجی بازبینی‌شده BOQ، برآورد و کوتیشن کن. قبل از تحویل، واحدها، مقادیر، موارد نامشخص و نرخ پیمانکار بررسی شوند. هزینه واقعی API و زمان اصلاح هر سفارش ثبت شود. بعد از سه مشتری پرداخت‌کننده و سفارش تکراری، پلن اشتراک قیمت‌گذاری شود؛ امکانات بیشتر به تنهایی اثبات فروش نیست.

## باقی‌مانده پیش از انتشار عمومی

- بررسی و اجرای migration در پروژه آزمایشی با نقش مالک، مدیر، viewer و کاربر نامرتبط.
- تست پرداخت Stripe در Test mode: شروع، پرداخت، بازگشت، تمدید، لغو و عدم پرداخت؛ سپس کنترل تنظیمات live.
- تست کامل چند پلان جدید JPG و DWG با خروجی مرجع و تعیین محدوده ورودی قابل پشتیبانی؛ بررسی فایل‌ها و URLهای ورودی تحلیل.
- بررسی RLS و storage برای جدول‌ها و فایل‌های قدیمی، مسیرهای APS و تمام داده‌های خصوصی، علاوه بر migration این بسته.
- بکاپ، بازیابی، مانیتورینگ خطا، پشتیبانی، شروط سرویس و سیاست نگهداری داده متناسب با عملیات واقعی.
