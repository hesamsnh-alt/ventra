# Ventra v45 — پروژهٔ کامل اصلاح‌شده

مبنای این نسخه فایل کامل «ventra 2.zip» ارسالی در ۹ اکتبر ۲۰۲۶ است. این پروژه برای یک نقشهٔ خاص تنظیم نشده است.

## اجرا

۱. فایل را در پوشه‌ای جدید استخراج کنید. فایل .env.local پروژهٔ خودتان را در آن کپی کنید؛ کلیدهای خصوصی در این بسته قرار ندارند. برای نصب تازه از .env.example استفاده کنید.
۲. npm ci را اجرا کنید.
۳. اگر دیتابیس v44 هنوز نصب نیست، scripts/INSTALL-VENTRA-v44.sql را در SQL Editor دیتابیس Supabase موجود اجرا کنید. فایل‌های جداگانهٔ همان migrationها هم بازگردانده شده‌اند. این نسخه تغییر تازه‌ای در schema ندارد. دیتابیس جدید نسازید و داده‌های قبلی را پاک نکنید.
۴. npm run dev را اجرا کنید. برای production: npm run build -- --webpack سپس npm start.
۵. تغییرات را در سرور تازه اجراشده آزمایش کنید؛ سرور قبلی را متوقف کنید و صفحه را با Ctrl+Shift+R بازخوانی کنید.

## تغییرهای این نسخه

- بازیابی چهار migration مفقود از همان installer داخل ZIP ارسالی.
- انتقال صحنه، هندسهٔ اصلی و نسخهٔ پشتیبان مبلمان JPG به IndexedDB؛ پرشدن localStorage دیگر مانع ذخیرهٔ این صحنه‌ها نیست. انتخاب DWG یا JPG نیز در پایگاه مرورگر نگهداری می‌شود.
- ذخیرهٔ اتمیک صحنه و مدل پایه، حفظ معماری هنگام تغییر سبک و مرتب‌سازی نوشتن‌های همزمان.
- حذف بارگذاری اولیهٔ تکراری نمایشگر؛ لغو بارگذاری‌های متعلق به پروژهٔ قبلی؛ بازسازی DWG پس از دریافت هندسهٔ ذخیره‌شده.
- تکمیل ترجمهٔ متن‌های ثابت باقی‌مانده به فارسی و عربی؛ حفظ عنوان وظیفه، نام مسئول، نام فایل، نام پروژه و شرح رکوردهای کاربر بدون ترجمهٔ ناخواسته.
- اصلاح وابستگی‌ها و خواندن آخرین وضعیت در callbackهای React؛ شناسهٔ جدید تحلیل در زمان درخواست ساخته می‌شود.
- جداسازی وضعیت نسخهٔ تجاری مشترک بر اساس پروژه، برای جلوگیری از استفادهٔ revision پروژهٔ قبلی.
- محافظ server-only برای سرویس‌های دارای کلید خصوصی.
- حذف پوشه‌های src/public و src/src و کپی‌های استفاده‌نشدهٔ ApsViewer. alias هدر و مسیر سازگاری APS حفظ شده‌اند، چون تداخل اثبات‌شده‌ای نداشتند.
- فشرده‌سازی تصاویر اصلی به WebP و اصلاح ارجاع‌ها.
- اصلاح متن دمو دربارهٔ قرارداد: ورود مراحل و تأیید پرداخت دستی است. دیدگاه‌های نمونه و ادعای تأییدنشدهٔ هزاران مشتری با توضیح روند کار جایگزین شده‌اند.
- فایل‌های محیطی خصوصی، ZIP پشتیبان توکار، node_modules و cache بیلد در بسته نیستند.

## منطق محصول

Estimate بودجهٔ تقریبی مستقل، با هشت سرفصل و نرخ قابل‌ویرایش مساحت است. BOQ تفکیک ردیف‌ها با مقدار، نرخ و وضعیت تأیید است. برابرشدن آنها اجباری نیست. حالت برآورد از BOQ به‌صورت جدا قابل انتخاب است. مقدار یا نرخ حل‌نشده نباید هزینهٔ صفر یا مقدار اندازه‌گیری‌شده جا زده شود.

DWG بدون واحد یا مرجع معتبر، اندازهٔ حدسی تولید نمی‌کند. جدول در و پنجره باید کامل و خوانا باشد و دو خوانش سازگار داشته باشد. دادهٔ نامطمئن نیازمند بازبینی باقی می‌ماند. در حالت تصویری، سبک‌ها فقط ارائهٔ سه‌بعدی را تغییر می‌دهند و مقادیر مهندسی را تغییر نمی‌دهند.

## محدودهٔ تأیید

گزارش docs/VALIDATION-v45.md نتیجهٔ تست‌های اجراشده را ثبت می‌کند. پذیرش تمام نقشه‌های دنیا، مترهٔ بی‌خطا، پرداخت زندهٔ Stripe، دسترسی واقعی چند کاربر به Supabase و کارکرد سه‌بعدی روی دستگاه شما با این بررسی محلی تضمین نشده است. متن‌های ثابت بررسی شده‌اند؛ متن‌های پویا، پاسخ سرویس‌های بیرونی و متن اصلی کاربر خارج از شمارش پوشش ثابت هستند. ترجمهٔ متن اصلی کاربر عمدی انجام نمی‌شود.

اخطار hydration با اختلاف فقط fdprocessedid به تزریق attribute توسط محیط مرورگر مربوط است؛ چنین attributeای در کد این پروژه وجود ندارد. اخطار کلی پنهان نشده است. آن مورد باید در مرورگر بدون افزونه هم بررسی شود.
