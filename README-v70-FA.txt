Ventra v70 — اصلاحات بر پایهٔ فایل «ventra 3.zip»
تاریخ: 2026-10-11

این پچ برای همان نسخهٔ کامل بررسی‌شده است. نسخهٔ نصب‌شدهٔ شما باید تغییرات قبلی آن پروژه را داشته باشد. فقط این فایل‌ها را روی پروژهٔ فعلی جایگزین کنید؛ پوشهٔ جدید ventra داخل ventra نسازید.

اصلاحات انجام‌شده:
۱) اصلاح تقسیم دیوار استنباطی در اتصال باز راهرو/لیوینگ، با حفظ بخش مجاور سرویس؛ دیوارهای مشاهده‌شده و بازشوهای متصل محافظت می‌شوند. تست جهت‌های چرخیده هم پاس شده است.
۲) کنترل مالکیت پروژه و مدل برای APIهای APS؛ توکن Viewer فقط اجازهٔ خواندن همان مدل تأییدشده را دارد.
۳) پروژه‌های مشترک: مدیر و ناظر می‌توانند مدل را ذخیره کنند؛ بیننده فقط می‌تواند بخواند. مسیر ذخیره را سرور از مالک واقعی پروژه تعیین می‌کند.
۴) پنل «همگام‌سازی ابری» در 3D، با ذخیرهٔ صریح مدل این دستگاه و بارگذاری مجدد. خطای ذخیره مخفی نمی‌شود.
۵) انتقال هر منبعِ ذخیره‌نشده به فضای ابری به صورت مستقل؛ وجود DWG دیگر جلوی انتقال مدل تصویری را نمی‌گیرد. بازیابی ابری مدل را دوباره روی سرور نمی‌نویسد.
۶) ذخیره و بازیابی رندرِ بررسی‌شده در فضای ابری، علاوه بر مدل تعاملی.
۷) جداسازی خطاهای اعتبار API، محدودیت موقت، تنظیمات کلید و مدل، و رد شدن تطابق پلان. محدودیت موقت زمان انتظار نشان می‌دهد. تلاش مجدد پولی خودکار انجام نمی‌شود؛ رندر پذیرفته‌شدهٔ قبلی با خطای جدید حذف نمی‌شود.
۸) بازگرداندن سهمیهٔ Ventra برای درخواست‌های ناموفق؛ ردیف دقیق همان درخواست حذف می‌شود، نه تاریخچهٔ مصرف. این کار اعتبار خرج‌شدهٔ OpenAI را برنمی‌گرداند.
۹) تکمیل ۱۷ مدخل ترجمهٔ باقی‌مانده در اسکن متن‌های ثابت رابط.

نصب:
۱) از پروژهٔ فعلی نسخهٔ پشتیبان بگیرید و سرور npm run dev را متوقف کنید.
۲) محتویات این پچ را در ریشهٔ پروژه کپی و فایل‌های هم‌نام را جایگزین کنید. ریشه همان پوشه‌ای است که package.json دارد.
۳) فقط فایل زیر را باز کنید و کل SQL آن را یک بار در SQL Editor همان پروژهٔ Supabase اجرا کنید:
supabase/migrations/20261011_release_failed_analysis.sql
اگر نصب تجاری v44 قبلاً انجام شده، SQLهای قدیمی را دوباره اجرا نکنید. این SQL جدید سهمیه‌های تاریخی را ریست نمی‌کند.
۴) در PowerShell همان ریشه اجرا کنید:
npm test
npm run check:locales
npm run build
۵) تغییرات پروژه و migration جدید را commit و push کنید؛ پس از Deploy موفق Netlify آزمایش کنید.

تنظیمات ضروری سرور:
Netlify باید همان پروژهٔ Supabase محیط محلی را داشته باشد. نام کلید سرویس مورد استفادهٔ کد SUPABASE_SERVICE_ROLE_KEY است. کلیدهای OPENAI_API_KEY، APS_CLIENT_ID و APS_CLIENT_SECRET نیز باید در محیط سرور تنظیم باشند. کلید خصوصی را با NEXT_PUBLIC_ نسازید و در GitHub قرار ندهید. این پچ تنظیمات حساب Netlify یا Supabase شما را خودکار تغییر نداده است.

مدل‌های CAD قدیمی:
مدل‌هایی که کلید شیء آن‌ها شامل مالک و پروژه نیست، برای حفظ جداسازی کاربران به بررسی مالکیت نیاز دارند. راه ساده، بارگذاری و تحلیل دوبارهٔ DWG است. راه دیگر تنظیم VENTRA_LEGACY_APS_MODELS روی سرور به صورت JSON نگاشت «URN کدگذاری‌شده: شناسهٔ پروژه» پس از تأیید مالکیت است. یک کاربر عادی نمی‌تواند مدل دلخواه را به نام خود ثبت کند. بعد از تغییر متغیرها دوباره Deploy کنید.

آزمایش گوشی:
روی لپ‌تاپ سایت Netlify را باز کنید، وارد همان حساب و پروژه شوید. در 3D پنل «همگام‌سازی ابری» را باز کنید و «ذخیرهٔ مدل این دستگاه در فضای ابری» را بزنید. باید پیام موفقیت ببینید. سپس روی گوشی همان سایت، حساب و پروژه را باز کنید و «بارگذاری مجدد از فضای ابری» را بزنید. خرید دامنه این مسئله را خودکار حل نمی‌کند.
ذخیرهٔ دستی مدل مشترک را جایگزین می‌کند؛ فقط روی دستگاهی ذخیره کنید که مدل صحیح را دارد. اگر روی لپ‌تاپ مدل فقط در localhost است، باید مدل را ابتدا در محیط سایت آنلاین ایجاد یا منتقل کنید؛ داده‌های مرورگر localhost در سایت Netlify در دسترس نیستند.

lint فایل‌های جدید اصلی و پنل‌های اصلاح‌شده: موفق. lint کل پروژه ادعا نشده است.

قبل از فروش عمومی هنوز باید در حساب واقعی شما بررسی شود:
- ذخیره/بازیابی مدل بین لپ‌تاپ و آیفون در محیط Netlify، با مدل JPEG و DWG و ورود مجدد؛
- اجرای APS با توکن محدود همان مدل و رد دسترسی کاربر خارج از پروژه؛
- ساخت رندر واقعی و تطابق دیوار، در، پنجره و اتاق با چند پلان مستقل فارسی، عربی و انگلیسی؛
- پرداخت آزمایشی Stripe، webhook، تمدید و لغو، و سهمیهٔ یک مشتری عادی؛
- سیاست بازپرداخت، اطلاعات اپراتور و متن نهایی Terms/Privacy؛
- تطابق مبالغ BOQ/Estimate/Quotation پس از همگام‌سازی صریح بخش تجاری.
پچ بدون اتصال به حساب‌های عملیاتی شما آزمایش شده است. رفع همهٔ مشکلات محصول و آمادگی قطعی برای فروش ادعا نمی‌شود. خطای shader/GPU گزارش‌شده باید روی مرورگر واقعی بازتولید شود؛ این پچ رفع آن را اثبات نمی‌کند.
