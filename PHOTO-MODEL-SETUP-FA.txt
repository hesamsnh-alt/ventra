Ventra v140 — کتابخانه مدل از عکس و اندازه بافت

نصب روی نسخه کامل پروژه‌ای که فرستادی:
1) سرور لوکال را با Ctrl+C متوقف کن و از پروژه فعلی نسخه پشتیبان بگیر.
2) محتوای پوشه src این بسته را داخل E:\ventra\src ادغام کن و جایگزینی فایل‌های همنام را بپذیر. پوشه src موجود را حذف نکن.
3) پوشه tests را هم در پوشه tests پروژه ادغام کن. هیچ وابستگی جدیدی لازم نیست.
4) در E:\ventra دستور npm run build و بعد npm run dev را اجرا کن.
5) برای انتشار Netlify، فایل‌های تغییرکرده و فایل‌های جدید src را به GitHub اضافه و push کن. کلیدها را commit نکن.

تنظیم تولید واقعی عکس به مدل:
یک حساب Meshy با کلید API و اعتبار جداگانه نیاز است. اعتبار OpenAI برای این کار مصرف نمی‌شود.
فقط این متغیرها را به .env.local موجود اضافه کن؛ فایل موجود را جایگزین نکن:
MESHY_API_KEY=کلید_خودت
MESHY_GENERATION_ENABLED=true
MESHY_DAILY_LIMIT=2
MESHY_GLOBAL_DAILY_LIMIT=10
در Netlify هم این چهار متغیر را در Environment variables تنظیم و دوباره deploy کن.
کلید فقط سمت سرور است؛ هیچ متغیر NEXT_PUBLIC برای Meshy نساز.
تا تنظیم کلید و فعال‌سازی، دکمه تولید عکس غیرفعال می‌ماند. آپلود متریال نیاز به Meshy ندارد.

دیتابیس:
سه جدول، تابع ثبت امن درخواست و bucket خصوصی ventra-personal-assets در Supabase متصل پروژه ventra ایجاد و بررسی شده‌اند.
فایل database/personal-assets.sql برای نصب روی پروژه Supabase دیگر ضمیمه شده؛ روی همین پروژه دوباره لازم نیست اجرا کنی.
جدول‌ها و دسترسی‌های قبلی، BOQ، قیمت‌ها و project-files تغییر نکرده‌اند.

استفاده:
- پنل مبلمان در 3D: کتابخانه مدل از عکس من ← آپلود عکس PNG/JPG/WebP ← انتظار برای تولید ← مدل خودکار در کتابخانه.
- پس از آماده‌شدن، مدل را انتخاب کن، اندازه واقعی عرض/عمق/ارتفاع بر حسب متر و نوع وسیله را تنظیم کن، «جای‌گذاری این مدل» و سپس روی کف کلیک کن.
- اندازه پیشنهادی فقط تناسب شکل مدل را حفظ می‌کند؛ اندازه واقعی از یک عکس قابل اندازه‌گیری نیست.
- پنل متریال: آپلود تصویر متریال، انتخاب، «استفاده از این متریال» و کلیک روی کف یا وجه دیوار.
- بعد از انتخاب سطح، اندازه تکرار بافت را بر حسب متر کم کن تا بافت ریزتر شود؛ مقدار بزرگ‌تر، بافت را درشت‌تر می‌کند. فقط همان وجه تغییر می‌کند. Ctrl+Z هم پشتیبانی می‌شود.
- کتابخانه شخصی است؛ برای نمایش در پروژه اشتراکی، دسترسی پروژه و اتصال مدل به پروژه بررسی می‌شود.

هزینه و بازیابی:
تولید Meshy پولی است؛ تازه‌سازی وضعیت، تولید جدید ایجاد نمی‌کند. ارسال دوباره همان عکس همان درخواست ذخیره‌شده را برمی‌گرداند.
سقف پیش‌فرض هر حساب ۲ درخواست در روز و کل سایت ۱۰ درخواست است. هر حساب فقط یک درخواست در حال انجام دارد.
اگر وضعیت ارسال نامشخص شد، خودکار دوباره درخواست پولی ارسال نمی‌شود؛ مدیر باید وضعیت سرویس و provider_id در ventra_model_jobs را بررسی کند. ردیف را بدون بررسی پاک نکن.
پردازش پس از ترک صفحه در سرویس ادامه می‌یابد؛ دریافت و ذخیره نتیجه با بازکردن کتابخانه و polling از سر گرفته می‌شود.

محدودیت و اعتبارسنجی:
149 تست کد و سرویس شبیه‌سازی‌شده موفق؛ build تولیدی Next.js موفق؛ تست مرورگر آپلود، انتخاب و ذخیره ابعاد موفق.
GLB واقعی کوچک با Three.GLTFLoader خوانده شده است، اما تولید پولی Meshy و رندر GPU در محیط کاربر تست نشده‌اند.
مدل تولیدی بازسازی تخمینی از یک عکس است و کیفیت/پشت جسم تضمین نمی‌شود. GLB غیرایستا، خارجی یا دارای افزونه فشرده‌سازی پشتیبانی‌نشده رد می‌شود.
در نمایشگر جایگزین قدیمی که GLB را پشتیبانی نکند، جای‌گذاری مدل شخصی با پیام روشن متوقف می‌شود.
حداکثر GLB برابر 25MB است. عکس ورودی تا 12MB و 24MP؛ تصویر قبل از ارسال کوچک می‌شود.

بازگشت:
پوشه rollback فقط نسخه قبلی فایل‌های جایگزین‌شده است؛ برای نصب عادی آن را کپی نکن.
برای بازگشت، فایل‌های آن را به مسیرهای اصلی برگردان؛ جدول‌های جدید خصوصی می‌توانند بدون تغییر باقی بمانند.
