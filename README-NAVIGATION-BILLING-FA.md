# نسخه اصلاح مسیرها و بخش‌های داخلی Ventra — ۲۰۲۶/۱۰/۰۶

این بسته از ZIP آخر شما ساخته شده و فایل‌های اصلی سه‌بعدی، متریال و تولید preview را تغییر نداده است.

## نصب
۱. از پوشه فعلی ventra یک نسخه پشتیبان بگیرید و سرور را با فشردن کلیدهای Ctrl+C متوقف کنید؛ عبارت Ctrl+C فرمان PowerShell نیست.
۲. محتوای این ZIP را داخل خود پوشه ventra جایگزین کنید. فایل شخصی .env.local را حفظ کنید؛ این ZIP کلیدهای شما را ندارد.
۳. در PowerShell:
```powershell
Set-Location 'C:\Users\hesam\OneDrive\Documents\vintra site\ventra'
npm ci
npm run build
npm run dev
```
از npm audit fix --force برای این اصلاح استفاده نکنید.

## مسیرهای وصل‌شده
- هدر: ابزارها، محصولات، قیمت، Billing، پشتیبانی؛ منوی حساب و خروج.
- فوتر: همه مقصدها به صفحه موجود وصل شده‌اند.
- داشبورد: آپلود، برآورد، BOQ و اسناد به انتخاب پروژه و تب مربوط می‌روند؛ حساب به Profile؛ اشتراک به Billing.
- /tools شامل محاسبه‌گرها و انتخاب پروژه برای BOQ، کوتیشن، برآورد، زمان‌بندی و اسناد است.
- /resources راهنمای جریان واقعی کار است؛ /support شماره WhatsApp موجود خود پروژه را حفظ می‌کند.
- صفحه موفقیت پرداخت وضعیت واقعی حساب را می‌خواند و صرف بازشدن صفحه اشتراک را فعال اعلام نمی‌کند.
- Documents اکنون از سرویس موجود Supabase برای فهرست، آپلود، دانلود و حذف استفاده می‌کند؛ داده نمایشی و متغیر تعریف‌نشده حذف شده‌اند.
- Tasks و Schedule قابل اضافه‌کردن، تغییر و حذف هستند. گزارش‌های روزانه نمونه جعلی ندارند و با کلید پروژه ذخیره می‌شوند. عکس گزارش به بخش اسناد همان پروژه وصل می‌شود.
- BOQ و Quotation: ویرایش، لوگو و سربرگ نسخه قبلی حفظ شده‌اند؛ داخل همان تب‌ها بخش Company branding قرار دارد.

## راه‌اندازی Billing
در .env.local تنظیم کنید (مقادیر واقعی را از حساب خودتان بگیرید):
```
STRIPE_SECRET_KEY=...
STRIPE_WEBHOOK_SECRET=...
NEXT_PUBLIC_STRIPE_STARTER_PRICE_ID=...
NEXT_PUBLIC_SITE_URL=https://your-domain.example
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=...
```
برای محیط توسعه NEXT_PUBLIC_SITE_URL می‌تواند http://localhost:3000 باشد. Stripe Customer Portal را در داشبورد Stripe فعال کنید. endpoint وب‌هوک /api/stripe/webhook است و فقط امضای واقعی Stripe را می‌پذیرد؛ نسخه قبلی اشتباهاً Checkout جدید می‌ساخت.
ابتدا با کلید و قیمت test، خرید، برگشت از Checkout، تغییر روش پرداخت، لغو و فاکتور را آزمایش کنید. پرداخت واقعی در این محیط اجرا نشده است.
Billing وضعیت اشتراک را مستقیم از Stripe می‌خواند. اشتراک فعال دوباره Checkout جدید نمی‌سازد. مشتری قدیمی فقط در صورت ارتباط معتبر metadata اشتراک با شناسه کاربر بازیابی می‌شود. محدودیت مصرف AI/تعداد پروژه و مجوز تجاری همه APIها با این تغییر به صورت سراسری enforce نشده‌اند.

## حدود این نسخه
- Tasks، Schedule، Daily Reports و بعضی پیش‌نویس‌های تجاری در مرورگر ذخیره می‌شوند؛ همگام‌سازی تیمی و بین دستگاه‌ها ندارند.
- Activity شمارش رکوردهای همین پیش‌نویس‌هاست؛ لاگ ممیزی سرور نیست. ایمیل و push فعال نیستند.
- Documents به جدول project_documents و bucket project-files و policyهای صحیح پروژه در Supabase نیاز دارد.
- صفحات Terms و Privacy صریحاً پیش‌نویس‌اند؛ متن نهایی حقوقی و مشخصات اپراتور باید قبل از انتشار تجاری تکمیل شوند.
- این بسته تأیید آمادگی تجاری کامل نیست: احراز هویت/مالکیت تمام APIهای AI و APS، سهمیه‌ها و ایزوله‌سازی داده باید جداگانه نهایی شوند.
