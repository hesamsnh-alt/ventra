Ventra v72 — گزارش روزانه، گزینه‌های آماده و بررسی عکس کارگاه
این پچ را پس از v70 و v71، روی پروژهٔ فعلی نصب کنید.

قابلیت‌های جدید:
- گزینه‌های آمادهٔ تعداد کارکنان، آب‌وهوا، مصالح، مشکلات، یادداشت و درصد پیشرفت؛ ورود متن و عدد دلخواه هم حفظ شده است.
- انتخاب عملیات: سازه، دیوارچینی، اندود، کف/کاشی، رنگ، برق، لوله‌کشی، تهویه، در/کابینت، عایق و محوطه.
- تعیین محل دقیق، اتاق و طبقه، و شرح کل محدودهٔ عملیات.
- دکمهٔ دوربین گوشی و انتخاب عکس؛ حداکثر ۶ عکس JPG/PNG/WebP قابل باز شدن در مرورگر. عکس‌ها برای ارسال و ذخیره به JPEG کوچک‌تر تبدیل می‌شوند.
- تحلیل دیداری: مرحلهٔ قابل مشاهده، شواهد، محدودیت‌ها، بررسی لازم و بازهٔ پیشنهادی تکمیل همان عملیات در همان محل.
- درصد فقط وقتی پیشنهاد می‌شود که کل محدوده مشخص و قابل مشاهده باشد. با عکس ناقص، سیستم باید توضیح دهد چه شواهد دیگری لازم است و درصد قطعی نمی‌سازد.
- واردکردن مقدار کل و انجام‌شده برای محاسبهٔ نسبت؛ مثلاً ۸ از ۲۰ مترمربع = ۴۰٪.
- تأیید صریح سرپرست پیش از ثبت درصد عملیات، با حفظ پیشنهاد AI و درصد نهایی به صورت جداگانه.
- ذخیرهٔ عکس‌ها در مدارک مشترک پروژه و پیوند آن‌ها به گزارش؛ دسترسی طبق مجوز پروژه.
- تمام کنترل‌ها و گزینه‌های جدید فارسی، عربی و انگلیسی هستند.

نصب:
۱) از پروژه پشتیبان بگیرید و npm run dev را متوقف کنید.
۲) پوشه‌های src، tests و supabase پچ را در ریشهٔ پروژهٔ فعلی کپی و فایل‌های هم‌نام را جایگزین کنید. پوشهٔ ventra دیگری داخل پروژه نسازید.
۳) فایل زیر را باز و تمام متن آن را یک بار در SQL Editor همان پروژهٔ Supabase اجرا کنید:
supabase/migrations/20261011_daily_report_evidence.sql
SQLهای قدیمی لازم نیست تکرار شوند. SQL این نسخه فقط ستون شواهد گزارش و محدودیت حجم/نوع آن را اضافه می‌کند. گزارش‌های قبلی حفظ می‌شوند.
۴) در ریشهٔ پروژه اجرا کنید:
npm test
npm run build
npm run dev
۵) برای سایت Netlify، فایل‌های پچ را commit و push کنید و منتظر Deploy موفق بمانید.

روش استفاده:
پروژه ← گزارش‌های روزانه ← افزودن گزارش.
گزینه‌های آماده را انتخاب و اطلاعات لازم را تکمیل کنید.
عملیات و محل را انتخاب کنید. «کل محدوده» را دقیق بنویسید؛ مثلاً «سرامیک کل کف آشپزخانه ۲۰ مترمربع با بندکشی».
عکس بگیرید یا از گالری انتخاب کنید. فقط اگر عکس‌ها کل محدوده را نشان می‌دهند، گزینهٔ پوشش کامل را فعال کنید.
«تحلیل عکس‌های کارگاه» را بزنید. بازهٔ پیشنهادی و محدودیت‌ها را بخوانید.
مقادیر اندازه‌گیری‌شده یا درصد نهایی تأییدشده را وارد کنید، تیک تأیید سرپرست را بزنید و گزارش را ذخیره کنید.

تفاوت اعداد:
«افزایش پیشرفت امروز» یک ورودی جدا و دستی برای گزارش روزانه است.
«پیشرفت تجمعی عملیات» درصد تکمیل یک فعالیت در محل مشخص است.
این دو با «پیشرفت کل پروژه» یکی نیستند. گزارش، زمان‌بندی و پیشرفت کلی پروژه را خودکار تغییر نمی‌دهد. وزن‌دهی مراحل مختلف یا تشخیص پیشرفت روزانه از مقایسهٔ خودکار عکس‌های تاریخی در این نسخه اضافه نشده است.

نیازهای حساب:
تحلیل عکس به OPENAI_API_KEY و اعتبار API نیاز دارد و از همان سهمیهٔ تحلیل پروژه استفاده می‌کند. با خطای اعتبار، درصد جعلی ثبت نمی‌شود. ذخیرهٔ گزارش دستی نیاز به درخواست AI ندارد.
مدل انتخابی از OPENAI_SITE_PROGRESS_MODEL، سپس OPENAI_3D_PREVIEW_MODEL و در نبود آن‌ها gpt-5.6-sol است؛ مدل باید ورودی تصویر و خروجی JSON ساختاریافته را پشتیبانی کند.
مدیر و ناظر پروژه مجاز به ثبت هستند؛ بیننده فقط خواندن دارد. دعوت سرپرست به تیم پروژه و تعیین نقش ناظر از قبل باید انجام شده باشد.
