Ventra v91 — رفع HTTP 504 هنگام تولید BOQ روی Netlify

تصویر 010243 نشان داد BOQ API پاسخ HTML با HTTP 504 می‌دهد. این نسخه تولید BOQ را، مانند تحلیل 3D، در تابع پس‌زمینه Netlify اجرا می‌کند. درخواست اولیه 202 و شناسه کار برمی‌گرداند و مرورگر نتیجه را از سرور دریافت می‌کند.

تمام منطق تولید اقلام، مقادیر، نرخ‌ها، طبقه‌بندی و محاسبات مالی فایل اصلی generate-boq بدون تغییر به ماژول سمت سرور منتقل شده است. احراز هویت، بررسی مالکیت پروژه و مسیر commercialRun مربوط به BOQ حفظ شده‌اند.
کارهای 3D قبلی همچنان سازگارند. کار BOQ به پردازشگر BOQ فرستاده می‌شود، نه پردازشگر تصویر. کلید پیگیری BOQ به پروژه، takeoff و تنظیمات مالی وابسته است تا نتیجه یک ورودی به ورودی دیگر وصل نشود.

نصب:
1) فایل‌های این پچ را در ریشه پروژه، کنار package.json، جایگزین کن. npm install بزن.
2) SQL جدید ندارد. اگر SQL جدول ventra_preview_jobs نسخه 89 اجرا شده، دوباره SQL اجرا نکن.
3) تمام فایل‌ها، شامل src، netlify، scripts، tests، package.json، package-lock.json و netlify.toml را commit و push کن.
4) پس از Published شدن Netlify، در سایت آنلاین Ctrl+Shift+R بزن، وارد پروژه شو و یک بار Generate BOQ را بزن.

تابع preview-background اکنون هر دو کار BOQ و 3D را پردازش می‌کند؛ تابع جداگانه‌ای با اسم boq-background لازم نیست. فرمان build در netlify.toml همان فرمان نسخه 89 است.
بسته شامل فایل‌های v89 و v90 هم هست و روی آخرین ZIP کامل شما تهیه شده است.

آزمایش آنلاین:
در Network درخواست POST generate-boq باید زودتر پاسخ 202 بدهد. پس از آن درخواست‌های کوتاه پیگیری در design-3d-preview?jobId=... دیده می‌شوند؛ این مسیر مشترک نتیجه هر دو نوع کار را برمی‌گرداند. پس از پایان، BOQ باید اقلام و مبالغ واقعی پاسخ سرور را نمایش دهد. 202 به معنی پایان تولید BOQ نیست.
اگر خطایی رخ داد، پاسخ Network و وضعیت آخرین کار در ventra_preview_jobs را بررسی کن. تشخیص 504 قبلی از روی عکس انجام شده؛ موفقیت زنده بعد از این نسخه هنوز در حساب شما تأیید نشده است.
این اصلاح دقت متره یا نرخ‌های بازار را تضمین نمی‌کند؛ آن‌ها باید جداگانه با پروژه واقعی بررسی شوند.
