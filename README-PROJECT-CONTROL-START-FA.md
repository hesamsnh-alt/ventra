# بخش اول کنترل پروژه — نصب و آزمایش

این نسخه بر ادامه ZIP اخیر شما ساخته شده است. بخش اعضا، دعوت و قرارداد اکنون به Supabase متصل است؛ با نصب migration فعال می‌شود. این بسته سیستم کامل کنترل اجرا یا تحلیل هوشمند مدارک نیست.

## نصب
۱. از پروژه و دیتابیس پشتیبان بگیرید؛ برای اولین اجرا ترجیحاً از پروژه آزمایشی Supabase استفاده کنید.
۲. محتوای این ZIP را در پوشه ventra جایگزین کنید؛ فایل شخصی .env.local را حفظ کنید. هیچ کلید خصوصی داخل این بسته نیست.
۳. در Supabase پروژه صحیح → SQL Editor → New Query، محتوای فایل زیر را کامل اجرا کنید:

supabase/migrations/20261006_project_control.sql

فایل داخل یک transaction اجرا می‌شود. جدول‌های قبلی پروژه حذف یا بازنویسی نمی‌شوند. فقط جدول‌های جدید و دسترسی‌های مخصوص این بخش ساخته می‌شوند. سیاست‌های قدیمی پروژه‌ها تغییر نمی‌کنند. اجرا روی دیتابیس واقعی شما از این محیط انجام نشده است.
۴. در مسیر اصلی ventra فرمان npm run build و سپس npm run dev را اجرا کنید.
۵. وارد پروژه شوید و تب Team & Contract را باز کنید.

## اعضا و دعوت
- مالک + یک عضو: سقف اولیه دو نفر برای هر پروژه است. این سقف هنوز سهمیه سراسری پلن Stripe نیست؛ برای فروش کاربران اضافه به اتصال entitlement نیاز داریم.
- مالک ایمیل و نقش را وارد می‌کند؛ کد تصادفی اختصاصی تولید می‌شود. کد خام فقط همان‌بار روی صفحه نشان داده می‌شود؛ دیتابیس فقط hash نگه می‌دارد.
- کد را خودتان خصوصی به گیرنده بدهید. برنامه ایمیل دعوت ارسال نمی‌کند و درگیر محدودیت ایمیل SMTP نمی‌شود، اما ساخت حساب جدید همچنان تنظیم صحیح Supabase Auth می‌خواهد.
- گیرنده با همان ایمیل وارد حسابش می‌شود؛ منوی هدر → Join / Shared projects → کد دعوت.
- اعتبار دعوت ۴۸ ساعت و یک بار استفاده است. دعوت منقضی ظرفیت را اشغال نمی‌کند؛ دعوت فعال استفاده‌نشده یک صندلی رزرو می‌کند. مالک می‌تواند دعوت را لغو یا عضو را حذف کند.
- اعضا وارد /project-control/PROJECT_ID می‌شوند و فقط تیم و قرارداد را می‌بینند. در این مرحله manager/supervisor/viewer همگی فقط خواندن دارند؛ تنها مالک ویرایش می‌کند. دسترسی به تمام تب‌های قدیمی، فایل‌ها و AI برای اعضا باز نشده است.

## قرارداد
- مبلغ AED، درصد retention، توضیح شروط تأیید/تسویه و مراحل پرداخت را دستی از قرارداد بررسی‌شده وارد کنید.
- مجموع درصد مراحل باید دقیقاً ۱۰۰ باشد. مثال شما به صورت پیش‌فرض ثبت نشده؛ شرایط هر پروژه را خودتان تعیین می‌کنید.
- Advance / Milestone / Final فقط نوع محرک پرداخت هستند؛ پیش‌پرداخت مساوی پیشرفت فیزیکی نیست.
- ثبت مبلغ و مراحل در یک عملیات دیتابیس انجام می‌شود؛ خطا هیچ نیمه‌قراردادی ذخیره نمی‌کند.
- مبلغ مراحل، برنامه ناخالص پرداخت است؛ به معنی وصول وجه یا مطالبه تأییدشده نیست. retention صرفاً ثبت می‌شود و خودکار کم نمی‌شود.
- اصلاح قرارداد فعلاً تاریخچه نسخه و امضای تأیید ندارد؛ قبل از اتصال به صورت‌وضعیت واقعی باید آن بخش اضافه شود.

## کنترل‌های انجام‌شده
- migration روی PostgreSQL تعبیه‌شده PGlite اجرا شد؛ اجرای دوباره آن هم آزمایش شد.
- تست نقش ناشناس/غریبه/عضو/مالک، ایمیل دعوت، سقف ظرفیت، انقضا، لغو و استفاده مجدد از کد، حذف عضو، جلوگیری از افزایش ظرفیت توسط عضو و atomic بودن قرارداد موفق بود.
- ۱۲ تست منطق قرارداد، درصد پروژه، Billing و اسناد تجاری موفق شد.
- lint فایل‌های جدید و build موفق؛ محیط build دارای Next 16.2.10 بود. package.json/lock با نسخه 16.3.8 شما حفظ شد.
- آزمون واقعی دو مرورگر متصل به Supabase شما و سیاست‌های قدیمی پروژه هنوز انجام نشده است. موفقیت تست محلی به معنی تأیید کل امنیت سایت نیست.

برای تکرار تست دیتابیس، @electric-sql/pglite را در یک مسیر آزمایشی جدا نصب کنید و متغیر VENTRA_PGLITE_MODULE را به dist/index.js آن تنظیم کنید؛ سپس node --test tests/project-control-sql.test.mjs را اجرا کنید. وابستگی جدیدی به برنامه اصلی اضافه نشده است.

## ادامه کار
ذخیره مشترک فعالیت‌ها و گزارش عکس، وزن‌دهی پیشرفت، تأیید سرپرست/معمار، ثبت دریافت وجه، هشدار تأخیر و استخراج AI از قرارداد/نقشه‌ها مراحل بعدی‌اند. Tasks و Schedule قبلی هنوز پیش‌نویس مرورگرند. خروجی سه‌بعدی و هندسه در این مرحله تغییر نکرده‌اند.
