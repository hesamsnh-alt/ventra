VENTRA BOQ EVIDENCE v37 — cumulative patch

نصب:
1. سرور توسعه را با Ctrl+C متوقف کنید.

3. پوشه‌های src و tests داخل ZIP را روی ریشه پروژه ventra کپی و فایل‌های هم‌نام را جایگزین کنید.
4. در PowerShell داخل پروژه اجرا کنید:
   npm run dev -- --webpack
5. صفحه BOQ را باز کنید. باید دکمه Review line کنار ردیف‌ها دیده شود.
6. برای حذف اثر بازنویسی قدیمی تعداد/واحد، پس از نگه داشتن خروجی قبلی، BOQ را یک بار دوباره Generate کنید.
   بازتولید BOQ تأییدها و ویرایش‌های دستی قبلی را حفظ نمی‌کند.
   در ترمینال باید [VENTRA BOQ EVIDENCE v37] دیده شود.

آزمون:
- ردیف دارای مقدار اندازه‌گیری‌شده ولی مشخصات تأییدنشده باید REVIEW REQUIRED باشد.
- با Review line سه موضوع مشخصات/دامنه، مقدار/واحد و نرخ را بررسی کنید و مرجع نقشه/نرخ بنویسید.
- فقط پس از تأیید کامل، ردیف وارد جمع reviewed می‌شود.
- مقدار، نرخ، واحد یا توضیح ردیف تأییدشده را تغییر دهید؛ تأیید باید لغو شود.
- برای اصلاح مقدار قفل‌شده، روی قفل بزنید و Unlock for editing را انتخاب کنید.
- بعد از بازخوانی صفحه، تأیید و مرجع آن باید در همان مرورگر باقی بماند.
- CSV/Excel باید ردیف تأییدشده را Yes و ردیف تأییدنشده را No نشان دهد.
- سپس در Estimate از Refresh استفاده کنید. حالت benchmark همچنان مستقل است.

رفتار مورد انتظار:
جمع تأییدشده ممکن است تا بررسی ردیف‌ها صفر یا کمتر شود؛ این به معنای هزینه صفر پروژه نیست.
Estimate با مبنای BOQ و Include provisional همچنان هزینه ردیف‌های تخمینی را شامل می‌شود؛
صرف تغییر وضعیت تأیید نباید مبلغ این حالت را عوض کند.
کد دیگر تعداد/مساحت کل در یا پنجره را روی همه ردیف‌ها نمی‌نویسد، واحد پنجره را با نرخ قدیمی
عوض نمی‌کند، و هنگام هر بار بارگذاری دوباره بازشوها را از سطح دیوار کم نمی‌کند.
